# Motor CPU — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans para ejecutar personalmente este plan, tarea por tarea, después de revisión por el usuario. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** entregar una CLI Rust que genere SVG/PNG reproducibles desde una plantilla SVG segura y un contrato versionado, sin GPU ni servicios externos.

**Architecture:** contrato neutral como fuente de tipos generados; crate core para reglas/importación, crate cpu para rasterización y crate cli para E/S. Usar el mismo core en el worker posterior. No crear API, cola, web, Python ni abstracción GPU vacía en esta entrega.

**Tech Stack:** Rust 1.99 disponible, Cargo, Rayon, usvg/resvg/tiny-skia, serde, serde_json, SHA-256 y Philox4x32-10. Generar estructuras desde JSON Schema mediante typify; confirmar compatibilidad antes de fijar dependencias. Base evaluada: resvg 0.47.0 y quick-xml 0.42.0; lockfile incluido. Registrar versiones/licencias en `docs/dependencias-motor.md`.

**Spec:** `docs/diseno-mvp.md`; contexto: `docs/adr/0001-arquitectura-inicial.md`, `docs/requisitos-fuente.txt` y `AGENTS.md`.

Estado: usuario confirmó tarea 1 el 2026-10-14. Se ejecuta solo esa tarea por ahora. Orden posterior corregido por el usuario: primero web contra motor, después Java. No pasar de fase 1 sin confirmación. Ver plan-desarrollo.md y ADR 0002.

## Global Constraints

- «CUDA es opcional: el proyecto debe compilar, probarse y ejecutarse completo sin CUDA.»
- «Sin dependencias propietarias obligatorias. Python/ML también es opcional para el flujo principal.»
- «Los tipos/clientes se generan desde contracts/; no se duplican modelos a mano.»
- Sin recursos externos, scripts, DTD, entidades, imágenes, texto/fuentes del sistema ni elementos SVG no admitidos.
- SVG máximo 5 MiB; 20,000 nodos; profundidad 64; 100,000 segmentos normalizados.
- Salida de 1–4096 px por eje, hasta 16,777,216 píxeles; máximo 10,000 variantes por solicitud.
- Máximo 8 intentos por variante; el rechazo conserva índice. Presupuesto de buffers 512 MiB; dos renders concurrentes iniciales como máximo.
- Transformaciones/color/capas originales; ningún código/asset de productos propietarios.
- No modificar LICENSE, CI o contratos publicados sin permiso. Estos contratos son nuevos, no publicados.
- Cada entrega se verifica antes de marcarla y hacer commit. No afirmar rendimiento aún no medido.

## Review Focus

1. SVG XML válido con atributos peligrosos, namespaces o entidades escapadas: rechazo antes de normalizar/renderizar (tarea 3).
2. Seed mayor que 2^53, índices extremos o intervalo que desborda u64: sin pérdida de precisión ni wraparound (tareas 1–2).
3. Variantes rechazadas o bloques reordenados: no alteran la aleatoriedad de las siguientes (tareas 2, 4, 6).
4. Cancelación, disco lleno o archivos de salida existentes: error claro, sin sobrescritura ni artefacto final parcial (tarea 6).
5. Referencias internas recursivas y expansión geométrica grande: límites aplicados antes de trabajo excesivo (tareas 3–5).

```text

services/engine/Cargo.lock                  Versiones reproducibles
services/engine/crates/core/                Contratos generados, RNG, SVG seguro y reglas
services/engine/crates/cpu/                 Raster PNG y límites de buffers
services/engine/crates/cli/                 Comandos, exportación incremental y cancelación
services/engine/tests/fixtures/             SVG originales y entradas de prueba
docs/dependencias-motor.md                  Versiones, licencias y fuentes
```

No añadir crate CUDA hasta implementar una segunda implementación real. Core no depende de cpu/cli. Los tipos locales geométricos no sustituyen modelos públicos del contrato.

## Convención de trabajo y comandos

Todos los comandos Cargo desde `services/engine`, usando ruta absoluta local si PATH no resuelve Cargo. Cada tarea: prueba que falla por la conducta faltante → implementación mínima → pruebas que pasan → revisión del diff → commit de archivos explícitos. Actualizar `docs/estado.md` con el resultado; guardar el hash en el registro del paso siguiente para evitar referencias circulares al propio commit.

Checks al finalizar tarea con cambios Rust:

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --locked
```

Esperado: cada comando devuelve exit code 0. No ejecutar toda la batería repetidamente sin un cambio nuevo o una preocupación sin resolver. No crear commits si fallan los checks.
